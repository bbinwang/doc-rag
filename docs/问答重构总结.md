# 问答重构总结

> 时间：2026-09-06

## 1. 概述

本次重构对问答模块进行了全面改造，核心变化是**从「选中文档后提问」改为「独立问答页 + 全库 chunk 级混合检索」**，每模式（plain / deep）独立完成召回、截断、LLM 调用，各自输出一份答案与召回明细，前端双栏对比展示。

## 2. 关键设计决策

### 2.1 问答与检索解耦

- **旧设计**：用户在搜索页勾选文档 → 问答基于选中 docIds 在每模式内做 BM25 检索 → 单次 LLM 调用（合并两模式上下文）
- **新设计**：问答页独立，不选文档 → 全库 chunk 级混合召回（BM25 + 向量 RRF）→ **每模式独立调一次 LLM**（双模式=两次调用）→ 各自输出答案与 chunks 明细

### 2.2 三参数可配置

| 参数 | 默认值 | 说明 | 配置文件 |
|---|---|---|---|
| `bm25-chunks` | 5 | 倒排路 chunk 召回上限 | `docrag.ask.bm25-chunks` |
| `vector-chunks` | 5 | 向量路 chunk 召回上限 | `docrag.ask.vector-chunks` |
| `context-chunks` | 8 | 重排后每模式送 LLM 的 chunk 上限 | `docrag.ask.context-chunks` |
| `context-char-budget` | 6000 | 每模式送 LLM 的字符预算 | `docrag.ask.context-char-budget` |

- 请求级可覆盖（`AskRequest` 中 `bm25Chunks` / `vectorChunks` / `contextChunks` 为 `Integer`，null 时走配置默认）
- 后端统一钳制 [1, 20]
- 生效值经 `AskParams` 回显到响应

### 2.3 失败隔离

- 某模式 0 chunk → 该模式返回占位提示「未检索到与问题相关的内容，无法作答」，不调 LLM
- LLM 调用失败 → 按模式隔离（`answer=null + error`，chunks 照常返回供调试）
- 仅当全部选中模式都失败才整体 500

## 3. 模块之间的交互

```
前端问答页 (ask.js)
    │  POST /api/ask { question, modes, bm25Chunks, vectorChunks, contextChunks }
    ▼
AskController
    │  AskParams.effectiveParams(配置默认, 请求覆盖) → 钳制 [1,20]
    ▼
AskService.ask()
    │  遍历每个选中模式（LinkedHashMap 保序）：
    │
    ├─► ModeSearcher.recallChunks(question, bm25Chunks, vectorChunks)
    │     │  BM25 路：全库 doc 召回 pool=clamp(bm25Chunks,5,20) → 入库同款切块
    │     │         → 问题分词重叠度排序取前 N
    │     │  向量路：vectorClient.query(mode, q, vectorChunks)
    │     │  chunk 级去重 + RRF(k=60) 融合
    │     │  返回 ChunkRecall(chunks[], degraded)
    │     │
    │     ├─► trimToBudget(selected, contextChunks, charBudget)
    │     │     贪心截断：按 RRF score 降序，累积字符不超过预算
    │     │
    │     ├─► 拼 prompt（system + 编号资料头 + user）
    │     │
    │     └─► LlmClient.chat(system, user)
    │            OpenAI 兼容 POST {base-url}/chat/completions
    │
    ▼
  组装 AskResponse(model, modes: {plain: {...}, deep: {...}}, params)
```

### 3.1 新增/修改的核心类

| 类 | 包 | 职责 |
|---|---|---|
| `Chunker.chunk()` | `indexer` | plain 模式切块（统一方法签名） |
| `Chunker.chunkKeepingTables(int)` | `indexer` | deep 模式块感知切块（256 chars） |
| `RecalledChunk` | `searcher` | chunk 级召回记录（docId/filename/type/path/title/source/score/text） |
| `ChunkRecall` | `searcher` | 单模式 chunk 召回结果（chunks + degraded） |
| `RankedDoc` | `searcher` | doc 级 BM25 召回结果（含 content 全文） |
| `AskParams` | `ask` | 三参数 + 生效值计算 |
| `AskModeResult` | `ask` | 单模式问答结果（answer/error/degraded/chunks/docs） |
| `AskChunk` | `ask` | 送入 LLM 的 chunk（ref 编号与答案 [n] 一一对应） |
| `AskDocRef` | `ask` | chunks 去重后的文档引用 |

### 3.2 被移除的类

| 类 | 原因 |
|---|---|
| `AskCitation` | 旧引用格式，被 `AskChunk` 替代（新增 source/score/title/text 调试字段） |

## 4. 检索逻辑重构

### 4.1 ModeSearcher 新增 recallChunks()

**新增方法**：`ChunkRecall recallChunks(String q, int bm25Chunks, int vectorChunks)`

**与 `search()` 的区别**：

| 维度 | search() — 检索页 | recallChunks() — 问答页 |
|---|---|---|
| 召回范围 | 按请求 docIds 过滤 | 全库（不限 docIds） |
| 排序粒度 | docId 级 RRF 融合 | chunk 级 RRF 融合 |
| BM25 召回策略 | TopK doc → RRF | doc 召回 pool → 入库同款切块 → 重叠度排序 |
| 高亮 | 有（Highlighter + `<em>`） | 无（返回完整 chunk text） |
| 截断 | page/size 分页 | 调用方负责（contextChunks + 字符预算） |

**BM25 路 chunk 召回流程**：
1. 全库 BM25 召回 `pool = clamp(bm25Chunks, 5, 20)` 篇文档（含 content 全文）
2. 对每篇文档按**入库同款切块策略**切块（plain=`Chunker.chunk`，deep=`chunkKeepingTables(256)`）
3. 对每个 chunk 与问题分词求 Jaccard 重叠度（`overlap()`），score > 0 的保留
4. 按 score 降序、doc rank 升序排序
5. 取前 `bm25Chunks` 个

**向量路**：直接调用 `vectorClient.query(mode, q, vectorChunks)`。

**chunk 级去重 + RRF**：
- 去重键：`(docId, chunk 精确文本)`
- RRF 常数：`k=60`（与 `search()` 一致）

### 4.2 search() 不受影响

`ModeSearcher.search()` 方法（检索页用）**未做功能改动**：
- 仍按请求 `docIds` 过滤
- 仍做 docId 级 RRF 融合
- 仍返回高亮 snippet
- 仅内部重构：`accumulateRrf()` 抽取了公共方法，逻辑等价

### 4.3 对原有搜索的影响

**无影响**。原因：
1. `search()` 方法签名和行为完全不变
2. 检索页前端（`main.js` + `index.html`）移除了旧嵌入式问答代码（勾选框、提问按钮、答案区），但搜索相关逻辑不变
3. 检索页 `main.js` 中遗留的 markdown 表格渲染代码被抽到独立文件 `md-table.js`
4. 检索页 `index.html` 中删除了旧问答 UI 区域（`ask-bar`、`ask-result`），仅保留搜索功能

## 6. API 变化

### 6.1 请求变更

**旧** `POST /api/ask`：
```json
{ "question": "xxx", "docIds": ["uuid1", "uuid2"], "modes": ["plain", "deep"] }
```

**新** `POST /api/ask`：
```json
{ "question": "xxx", "modes": ["plain", "deep"], "bm25Chunks": 5, "vectorChunks": 5, "contextChunks": 8 }
```

- 移除 `docIds`（不再选中文档）
- 新增 `bm25Chunks` / `vectorChunks` / `contextChunks`（可选，null=配置默认）

### 6.2 响应变更

**旧**：
```json
{ "answer": "xxx", "model": "gpt-4o-mini", "modes": ["plain","deep"], "citations": [...] }
```

**新**：
```json
{
  "model": "gpt-4o-mini",
  "params": { "bm25Chunks": 5, "vectorChunks": 5, "contextChunks": 8 },
  "modes": {
    "plain": {
      "answer": "xxx", "error": null, "degraded": false,
      "chunks": [{ "ref": 1, "docId": "...", "filename": "...", "source": "both", "score": 0.03, "text": "..." }],
      "docs": [{ "docId": "...", "filename": "...", "type": "...", "path": "..." }]
    },
    "deep": { ... }
  }
}
```

- 响应结构从扁平数组改为嵌套 `modes`（与 `/api/search` 同构）
- 每模式独立 `answer` / `error` / `degraded` / `chunks` / `docs`
- `chunks` 新增 `source`（both/bm25/vector）、`score`（RRF 融合分）、`text`（完整块文本）、`title`（deep 表格块）

### 6.3 新增端点

`GET /api/ask/params` — 暴露三参数默认值（前端问答页初始值）
