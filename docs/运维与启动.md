# 运维与启动 —— 三服务启动、端口、配置、清理与数据目录

> 本文回答：三个服务怎么起、按什么顺序起？端口和路径有哪些坑？全部配置项在哪？一键清理和「删目录重建」的边界是什么？
> 契约与语义类内容不重复本文（API 见《[api.md](api.md)》，降级语义见《[检索与召回](检索与召回.md)》§4）。

## 1. 服务与端口

| 服务 | 端口 | 进程 | 说明 |
|---|---|---|---|
| Java 后端 | 8080 | Spring Boot（`server.port`） | REST 主体，必启 |
| Flask 前端 | 3000 | `flask run` / `app.run`，host 0.0.0.0 | 服务端渲染，必启；端口硬编码于 `app.py` |
| vector-service | 8081 | FastAPI + uvicorn，host 0.0.0.0 | **可选**；不启则检索/问答自动降级纯 BM25 |

- host 0.0.0.0 意味着**局域网可访问**（前端与 vector-service 均如此）；仅本机用时注意。
- 本机端口约定：8081 固定为本项目 vector-service（Java 侧 `vector-service-url`、多处文档硬编码，勿改）；临时测试/冒烟避用 18000，常用冒烟端口 18971 / 18972 / 18080 / 13000。

## 2. 启动顺序与命令

顺序：**vector-service（可选）→ Java 后端 → 前端**。后端启动时只 ping 不依赖 vector-service 存活；先起 vector-service 是为了让首次检索/上传即可用双路召回。

```bash
# 0. JDK（brew 安装的 openjdk@17 需显式指定）
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"

# 1. [可选] vector-service —— 两种方式等价：
cd vector-service && pip install -r requirements.txt
python main.py                          # 走 main.py 末尾 uvicorn.run，读 DOCRAG_PORT（默认 8081）
uvicorn main:app --host 0.0.0.0 --port 8081   # 显式 uvicorn，效果相同
# 首次启动若 models/bge-small-zh-v1.5/ 快照缺失会联网下载（约 130MB）；快照在则全程离线

# 2. Java 后端（默认 :8080）
cd backend && mvn spring-boot:run

# 3. 前端（默认 :3000）
cd frontend && pip install -r requirements.txt && flask run --host 0.0.0.0 --port 3000
```

**路径大坑**：`application.yml` 里的 `../data/*` 是**相对进程 cwd** 的——从 `backend/` 启动才正确；从其它目录启动必须显式传绝对路径（如 `-Ddocrag.upload-dir=/abs/path/data/upload`），否则会在 cwd 旁边新建一套空目录。

## 3. 配置清单

### Java 后端 `backend/src/main/resources/application.yml`

| 配置项 | 默认 | 说明 |
|---|---|---|
| `server.port` | 8080 | |
| `spring.servlet.multipart.max-file-size` / `max-request-size` | 50MB / 55MB | 超限 413 |
| `docrag.upload-dir` | `../data/upload` | 相对 cwd（见上坑） |
| `docrag.plain-index-dir` / `deep-index-dir` | `../data/index-plain` / `../data/index-deep` | 各模式倒排目录 |
| `docrag.vector-service-url` | `http://127.0.0.1:8081` | |
| `docrag.llm.active` | env `DOCRAG_LLM_ACTIVE`（yml 默认 `glm`） | 当前启用的 provider 名，对应 `providers` 的 key；切换 LLM 只改这一项 |
| `docrag.llm.providers.<name>.base-url` | env `DOCRAG_LLM_<NAME>_BASE_URL` | OpenAI 兼容，**不含** `/chat/completions` 后缀；yml 维护 `glm`（智谱 `https://open.bigmodel.cn/api/paas/v4`）与 `mac-uni`（内网，保留不启用）两个 provider |
| `docrag.llm.providers.<name>.api-key` | env `DOCRAG_LLM_<NAME>_API_KEY` | active provider 的 key 为空视为未配置，`/api/ask` 400 |
| `docrag.llm.providers.<name>.model` | env `DOCRAG_LLM_<NAME>_MODEL` | glm=`glm-5.3`、mac-uni=`mac-uni-model` |
| `docrag.llm.providers.<name>.temperature` | 0.2 | |
| `docrag.llm.providers.<name>.timeout-seconds` | glm=120、mac-uni=60 | |
| `docrag.ask.bm25-chunks` / `vector-chunks` / `context-chunks` | 5 / 5 / 8 | 问答三参数默认（前端初始值走 `GET /api/ask/params`，改 yml 即时生效） |
| `docrag.ask.context-char-budget` | 6000 | 每模式字符预算，不开放请求覆盖 |

### 前端 `frontend/app.py` 常量

| 常量 | 值 | 说明 |
|---|---|---|
| `API_BASE` | env `DOCRAG_API`，默认 `http://127.0.0.1:8080` | 后端地址（唯一可配项） |
| `PAGE_SIZE` | 10 | 检索分页 size |
| `MAX_DOC_CHARS` | 200_000 | 原文展示截断（索引中仍是全文） |
| `ASK_TIMEOUT` | 180 | 问答转发超时（双模式串行两次 LLM） |
| `ASK_PARAM_DEFAULTS` | 5/5/8 | 后端不可达时问答页参数回退 |

### vector-service 环境变量

`DOCRAG_EMBED_MODEL` / `DOCRAG_CHROMA_DIR`（默认 `data/chroma`）/ `DOCRAG_PORT`（默认 8081），详见《[vector-service](vector-service.md)》§5。

### 前端各转发超时一览

搜索/状态 10s；debug/上传 120s；ask 参数 5s；明细类 15s；清理 60s；问答 180s。

## 4. 一键清理与数据目录

- **一键清理**（`POST /api/admin/clear`，前端状态条按钮）：先探测 vector-service（不可用直接 400 拒绝），再清双 collection → 双倒排（`IndexWriter.deleteAll()`）→ **删除 `data/upload/` 全部上传原文件**（目录保留）。全量清空语义，confirm 弹窗已明示不可恢复。
- **数据目录均可删重建**：`data/index-plain/`、`data/index-deep/`、`data/chroma/` 均在 .gitignore，停服后整目录删除 = 该库清零，重启自动重建；`data/upload/` 删除则原文件丢失（索引仍在，但无法重新解析入库）。
- 索引与向量库不一致的兜底：删除文档是级联的（先双 collection 后双倒排）；若发生不一致，以「清空重建」为最终手段。

## 5. LLM 问答配置

多 provider 结构：`docrag.llm.providers.<name>.*` 维护多个 OpenAI 兼容 LLM，`docrag.llm.active`（env `DOCRAG_LLM_ACTIVE`）选出**唯一启用**的 provider，其余仅存配置不生效。yml 目前维护两个：

| provider | base-url | model | 状态 |
|---|---|---|---|
| `glm` | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3` | **启用**（默认） |
| `mac-uni` | `http://192.168.2.122:3000/v1` | `mac-uni-model` | 保留不启用 |

```bash
# 切换 provider（不改 yml）
export DOCRAG_LLM_ACTIVE=mac-uni
# 覆盖单个 provider 的连接参数（NAME 大写，如 GLM / MACUNI）
export DOCRAG_LLM_GLM_BASE_URL="https://open.bigmodel.cn/api/paas/v4"
export DOCRAG_LLM_GLM_API_KEY="..."
export DOCRAG_LLM_GLM_MODEL="glm-5.3"
```

`active` 未设置、指向不存在的 provider、或其 api-key 为空 → `/api/ask` 返回 400；本地不跑模型、只调远端 `/chat/completions`。调用语义见《[问答设计](问答设计.md)》。
