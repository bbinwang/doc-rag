# ADR-0001：问答重构为全库 chunk 级检索 + 每模式独立 LLM

- 状态：已采纳
- 日期：2026-09-06
- 背景快照：《[../archive/问答重构总结](../archive/问答重构总结.md)》（含新旧 API diff、类增删、测试数等过程细节）

## 背景

旧问答是「搜索页勾选文档 → 限定 docIds 在每模式内 BM25 检索 → 合并两模式上下文单次调 LLM」。问题：

1. 检索失误直接传导为问答失误——用户必须先搜对、选对文档；
2. 词面不重叠的 chunk 被分词重叠度排序误杀（问「试用期上限」，文档写「不超过六个月」）；
3. 单次 LLM 调用合并两模式上下文，答案证据无法归属到解析模式，也无法按模式隔离失败。

## 决策

1. **问答与检索解耦、与选文档解耦**：问答独立成页（`/ask`），全库 chunk 级混合召回（BM25 路 doc 召回→入库同款切块→overlap 排序 + 向量路，chunk 级 RRF 融合），不选文档。
2. **每模式独立调一次 LLM**：双模式 = 两次调用，各自输出答案 + 召回明细（`chunks[].ref` 与答案 `[n]` 一一对应），前端两栏对比。
3. **三参数可配置**：`bm25-chunks` / `vector-chunks` / `context-chunks`（请求覆盖 → 配置默认 → 钳制 [1,20]，生效值回显），另有不开放覆盖的 `context-char-budget`。
4. **失败按模式隔离**：某模式 0 chunk → 占位提示不调 LLM；LLM 失败 → 该模式 `answer=null + error`、chunks 照常返回；仅全部模式失败才 500。不降级编造答案。

## 理由

- 检索责任交还系统：chunk 级向量召回天然覆盖「词面不重叠」的语义命中，优于人工选文档；
- overlap 排序降级为 BM25 路**内部**的排序信号，不再淘汰向量路结果（`source=vector` 的 chunk 也能进上下文）；
- 每模式独立调用换来免费的失败隔离与 plain/deep 可对比性；代价是双模式延迟与 token 翻倍，本地场景可接受；
- 三参数开放请求级覆盖，让「召回多少、送多少」可以在问答页按次实验，不必改代码重启。

## 后果

- 正面：答案可追溯（ref↔[n]）、模式可对比、失败可诊断（chunks 明细照常返回）；
- 负面：双模式延迟翻倍（前端 `ASK_TIMEOUT=180s` 兜底）；chunk 级去重依赖「检索期切块 = 入库期切块」这一硬前提（见《[../解析与入库](../解析与入库.md)》§4.3）；
- 中性：`/api/ask` 请求移除 `docIds`、响应改嵌套 `modes` 形状（与 `/api/search` 同构），旧客户端不兼容——一次性切换，未做兼容期。
