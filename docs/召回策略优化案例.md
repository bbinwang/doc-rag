# 召回策略优化案例 —— 从「生产环节模具组装需要哪些大类的材料」说起

> 本文回答：2026-09-21 那次问答召回优化到底改了什么、**为什么有效**——用一个真实 query 的三阶段实测对比展开。
> 实测环境：corpus_complex 语料 15 篇、glm、`bm25/vector/context-chunks = 5/5/8`（全部默认值）。
> 机制的定义与全貌见《[检索与召回](检索与召回.md)》§3 与《[双路召回chunk的原理](双路召回chunk的原理.md)》；本文是案例实录，数据有时点性，方法论长期有效。

## 1. 案例背景

**问题**：`生产环节模具组装需要哪些大类的材料`

**期望答案**（目标文档《浙江省装配式建筑职业技能竞赛实施方案.docx》物料清单表，24 行，eval 用例 E4）六大类：

> 劳保材料、技术准备、模具、材料（钢筋/预埋件/脱模剂/保护层垫块/绑丝/吊杠/绑扎工具）、设备工具、检测工具

**语料环境**（干扰画像，后面反复出现）：

| 干扰源 | 特征 | 为什么难缠 |
|---|---|---|
| FinGLM 系列 xlsx（行业分类表/年报摘要等） | 拍平后每行一条「公司名__代码__行业」记录，plain 向量库 **9326 条**行级 chunk | 问题含「材料」，bge 对「新材料/再生资源」类公司名行相似度 0.48–0.51，量大人多 |
| 年报 PDF（安靠智电/金宇生物） | 每篇数万字长文 | 满篇「生产/需要/材料」等通用词，词频计分时代天然刷分王 |

## 2. 优化前：双模式全灭（实测）

### 2.1 plain：上下文 8 块无一来自目标文档，LLM 诚实拒答

> **答**：无法从提供的参考资料中找到答案。所提供的参考资料内容包括：金宇生物 2020 年年度报告中关于股份支付会计处理 [1] 以及资产减值测试（商誉减值）的会计政策 [7]；安靠智电 2019 年年度报告中关于借款费用资本化 [3]……

| ref | 文档 | source | 内容 |
|---|---|---|---|
| [1][5][7] | 金宇/安靠年报 | bm25 | 股份支付 / 或有事项 / 借款费用资本化（会计政策） |
| [2][4][6][8] | FinGLM 行业分类表/年报摘要 | vector | 汉威科技 / 海螺新材 / 复旦微电 / 海顺新材 公司名行 |

目标文档 **0/8**。检索层全错，LLM 拒答是正确行为——错在召回。

### 2.2 deep：直接「未检索到与问题相关的内容，无法作答」（0 chunk）

doc 池其实召回了目标文档（诊断探针：deep 检索 top1 就是目标 doc 0.033），但语料里有 7 万字符的整 sheet 原子表块（FinGLM 大表），它在旧计分下排融合序前列，一进 `trimToBudget` 就撞穿 6000 字符预算——而旧逻辑是 **break**：首个超预算块直接终止装填，该模式上下文清零 → 0 chunk 占位、连 LLM 都不调。

### 2.3 根因链（四条，各配实测证据）

**① 通用词污染 doc 召回池。** 旧池查询把问题全部词项 OR 起来。IK 对问题的切词（smart 与 fine 实测完全一致）：

```
[生产][环节][模具][组装][需要][哪些][大类][的][材料]
```

df 实测（`/api/search` total，N=15）：**生产 11、需要 11、材料 10、的 14**——四成以上的词六成以上文档都有。含这些词的 FinGLM 行与年报块在 BM25 下得分不低（诊断探针：完整问题检索页 plain top5 全是 FinGLM/安靠 both 0.030–0.032，目标 doc 0.016 排第 6，进不了 pool=5 的池子）。

**② 出现次数计分，无权重、可刷分。** 旧 overlap 数「命中问题词项的次数」：年报整块「材料」出现几十次就得几十分，块越长越占便宜；「模具」这种一锤定音的判别词和「的」同权。

**③ `trimToBudget` break 语义。** 超大块一票否决整个模式的上下文（§2.2）。

**④ 融合序纯 RRF。** 向量路 plain top6 实测**全是 FinGLM 行**（sim 0.48–0.51），RRF 只看排名：FinGLM 行的 `1/(60+k)` 与真块并列，`contextChunks=8` 的名额被吃掉一半。deep 侧向量 top6 恰好全是目标文档（sim 0.49–0.73，表格 1 原子块 0.507 排第 5）——同一套向量路，语料不同命运不同，说明不能靠「调大 topK」解决 plain。

## 3. 三个改动，以及为什么有效

### 3.1 判别词过滤 + IDF 加权 —— 池子只由「有判别力的词」决定

问题词项先按索引 df 过滤（df=0 丢弃；df > 60%×N 剔除；全剔光回退原始词项），保留词赋 IDF 权重 `ln(1+(N-df+0.5)/(df+0.5))`，再做池查询与计分。本例实测：

| 词 | df | 占比 | 处置 | IDF 权重 |
|---|---|---|---|---|
| 的 | 14/15 | 93% | **剔除** | — |
| 生产 / 需要 | 11/15 | 73% | **剔除** | — |
| 材料 | 10/15 | 67% | **剔除** | — |
| 大类 | 8/15 | 53% | 保留 | 0.63 |
| 环节 / 模具 / 哪些 | 7/15 | 47% | 保留 | 0.76 |
| 组装 | 6/15 | 40% | 保留 | 0.90 |

**为什么有效**：剔除的恰是 FinGLM 行与年报块的「得分来源」——它们 content 里根本没有「模具/组装/环节」。池查询换成判别词布尔查询后，能在 doc 池里存活的只剩真含这些词的文档；「材料」这种六成文档都有的词不再有投票权。这不是把某个干扰文档拉黑，而是让**问题自己说出哪些词值得信**。

### 3.2 去重覆盖（同词只计一次 × IDF）—— 长块刷分失效

chunk 计分从「出现次数和」改为「判别词去重覆盖 IDF 加权和」：每个判别词无论出现多少次只计一次覆盖。

- FinGLM 行块「…海顺新型药用**包装材料**股份有限公司…」：判别词覆盖 = **0**（环节/模具/组装/大类/哪些一个都没有）→ BM25 路直接出局，连候选都不是；
- 目标文档表头块「（一）**生产环节模具组装**（每组用量）分类 序号 名称…」：覆盖 环节 0.76 + 模具 0.76 + 组装 0.90 ≈ **2.42**。

**为什么有效**：块间竞争从「谁长、谁重复多」回归「谁覆盖了问题的判别词」。旧计分下 7 万字年报块可以靠「材料」×几十次拿最高分，新计分下它和一个 500 字块站在同一起跑线——每个词只有一票，票的权重由稀有度决定。

### 3.3 `trimToBudget` break → continue —— 巨块跳过，不再一票否决

单块超剩余字符预算改为**跳过该块继续装填**。

**为什么有效**：deep 整 sheet 原子块（数万字符）本来就该被预算拦住——错的是连带把后面 1021 字的表格 1、正文块一起拦掉。改后巨表出局、正常块照常进入上下文，deep 的 0-chunk 硬失败（§2.2）就此消除，这是 deep 侧本轮从「未检索到」直接跳到「六大类完整」的第一功臣。

### 3.4 融合序词锚定优先 —— 语义噪声沉底，不清除

RRF 融合后排序加一层分组：**与判别词有重叠（BM25 命中或覆盖>0）的锚定组在前、组内 RRF 降序**；零重叠纯向量块沉到组后，但不清除。

**为什么有效**：FinGLM 行块判别词覆盖为 0（§3.2），锚定组永远进不去；而它的 RRF 分与真块并列（§2.3 ④），纯 RRF 序下靠排名吃名额。锚定分组后，8 个名额先由锚定块填——FinGLM 从「[2][4][6][8] 交错」变成「[6][7][8] 垫底」。

**为什么不清除（安全边界）**：纯改写问题（词面与文档完全不重叠，如问「试用期上限」文档写「不超过六个月」）全库零锚定时锚定组为空，向量序原样生效，语义召回能力无损。回归实测：改写题 F1（「按威海市残联的普法规划……什么时间报送」）双模式照常 both 命中、正确作答。

## 4. 三阶段实测对比

同一 query、同一语料、同一 LLM，只动召回策略：

| 阶段 | plain 答案 | plain 上下文构成 | deep 答案 |
|---|---|---|---|
| **0 优化前** | 拒答（上下文全是年报会计块） | 目标 0 + 年报 4（bm25）+ FinGLM 4（vector） | 「未检索到」（0 chunk） |
| **1 判别词+IDF+跳过装填** | 引用竞赛流程正文「模具、钢筋、预埋件、其他材料及工具」（方向对、出处错） | 目标 3 + 安靠 1（bm25）+ FinGLM 4（vector） | **六大类完整** ✓ 表格 1 块进入上下文 |
| **2 +词锚定** | 引用物料清单表头块，答出四大类 4/6（劳保/技术准备/模具/材料） | 目标 4 + 安靠 1（bm25 锚定前置，含表头块）+ FinGLM 3（沉底） | 六大类完整 ✓ |

plain 上下文的块级演变（ref = 送 LLM 顺序）：

```
阶段0  [1]金宇   [2]FinGLM [3]安靠   [4]FinGLM [5]安靠   [6]FinGLM [7]金宇   [8]FinGLM
阶段1  [1]竞赛   [2]FinGLM [3]竞赛   [4]FinGLM [5]安靠   [6]FinGLM [7]竞赛   [8]FinGLM
阶段2  [1]竞赛   [2]竞赛   [3]安靠   [4]竞赛   [5]竞赛▸  [6]FinGLM [7]FinGLM [8]FinGLM
                                                    ▸ = 物料清单表头块（本轮关键增量）
```

每步改动的归因：

- **判别词+IDF（阶段 0→1）**：目标文档第一次进池、第一次有块进上下文；安靠年报仍有 1 块混入（它恰好含「模具」无关但含「组装/环节」之类词面的段落，判别词覆盖>0，属策略内的合理竞争）；
- **跳过装填（阶段 0→1，deep 侧）**：deep 从 0 chunk 到六大类完整，单点修复收益最大；
- **词锚定（阶段 1→2）**：FinGLM 从名额内交错沉到底部，表头块顶替其位置进入上下文——plain 的答案出处从「竞赛流程正文」修正为「物料清单表」。

## 5. 残留限制：plain 为什么是 4/6 而不是 6/6

plain 的 512 字符贪心合并把 24 行物料清单切成两块：表头块 [5]（519 字）恰好在「材料」类处截断，**设备工具/检测工具两类的行（滚刷、卷尺、插片……）落入后继块**——后继块与问题判别词零重叠，任何词锚定都无法召回它。这是 plain「拍平文本 + 定长切块」的结构性边界，也正是 deep 表格原子块（表格 1 整表 1021 字一个 chunk）存在的意义：同一个页面两栏对比，deep 给全六类、plain 给表头能看到的四类，差异本身就是模式选择的依据。
